# Audyt PR-28 (2026-09-09, sesja PR-29)

Zakres: `98b1f02..0520ffc` — PR-28 „Kaladesh: odrzucenie jednowarstwówki,
LOD ścieżką Dominarii + materializacja 610M19” (41 plików, +6358/−120),
scalony 2026-09-09.

Sesja audytująca: `arena/01a0874a-mtg`.

## 1. Integralność bazy (stan PO PR-28)

- Klon sesji był płytki i PIERWSZE `git fetch --unshallow` wygasło z
  exit 0, nie pobierając historii (`.git/shallow` odtworzone drugim
  fetchem); zweryfikowano stan po odbudowie: `git rev-list --count HEAD`
  = 26, rodzic `0520ffc` istnieje. **Lekcja operacyjna:** unshallow
  weryfikuje się licznikiem commitów i `git cat-file -e <rodzic>`,
  nie flagą `is-shallow-repository`.
- `npm test` **176/176, 0 pominiętych** (pełne środowisko: python3,
  ImageMagick, manifest Dominarii). Liczby w dokumentach PR-28 różnią
  się od siebie — patrz znalezisko **N2**.
- `npm run build` zielony — **31 stron (15 kart, 4 hasła, 12 planów)**,
  ZIP 87 756 kB (87,7 MB) — zgodne z handoffem.
- `python3 tools/map-audit.py` = **0 problemów** (w tym nowe pkt 8–9:
  geometria miasta i płyty L2).
- Mini-mapy: sandbox Areny nie ma `node_modules` (snapshot wyklucza
  katalog; build jest czystym Node, a detekcja rasterizatora ma
  fallback). Wynik: mini-mapa = pełna baza wektorowa (fallback
  z `build.mjs`), identyczny stan jak w sesji PR-28 (ten sam rozmiar
  ZIP). Cecha środowiskowa, nie wada PR-28.
- Uwaga środowiskowa: `dist/` nie jest utrwalane między turami
  (katalog wykluczony ze snapshotu) — główny artefakt (`index.html`,
  `mtg-lore-codex.html`, ZIP) trzeba w sesji odtworzyć buildem;
  wykonano (podgląd: `python3 -m http.server --directory dist 8000`).
